## 一、必做的四项配置

群里「发指令没反应」99% 是这四项没配。**按顺序做完再测**。

| # | 位置 | 要做什么 | 不做的后果 |
|---|---|---|---|
| 1 | AstrBot → 配置 → 平台与消息 → **唤醒词** | 添加 **`.`**（想支持全角再加 `。`） | 所有 `@filter.command` 指令（`.st` `.pc` `.bot` `.log` …）**全部无反应且不报错**；`.r` `.ra` `.sc` 仍能用，因为走插件自己的内联解析 |
| 2 | AstrBot → 配置 → 访问控制 → **白名单 ID 列表** | 添加**群号**（纯数字，如 `1299596251`） | 普通群成员的消息会被 AstrBot 直接掐断，插件收不到 |
| 3 | 插件配置 → **管理命令管理员 ID**（`admin_ids`） | 填**你的 QQ 号**，逗号分隔（如 `1299596251,10001`） | `.sc reset` 谁都用不了 |
| 4 | QQ 群 → 群设置 | 把**机器人设为群管理员** | `.st`／`.sc` 后自动改群名片会报 `retcode=1200 设置群名片未生效`（属性照常保存，只有名片失败） |

另有一个插件配置项值得知道：

- `san_auto_int_check`（默认 `true`）：理智单次损失达阈值后**自动掷 INT** 判定惊骇。设为 `false` 则只提示「需 kp 裁定」，由 kp 手工掷。

> 排查口诀：群里先发 `.bot status`。有回应 → 唤醒词没问题；没回应 → 是配置 1 或 2 的问题，跟插件代码无关。

## 二、5 分钟上手：创建一张 CoC 角色卡

```text
# 1. 建卡并自动绑定到当前群（一个群同时只有一张"当前卡"）
.pc create 文武
#    → 已创建人物卡 <文武>，编号：4ce455e4-…

# 2. 录属性：中文名或英文缩写都认，一整串贴进来一次写完
.st 力量60 str60 敏捷25 dex25 体质85 con85 外貌45 app45 智力85 int85 意志75 pow75 体型65 siz65 教育49 edu49 hp15 san75 克苏鲁神话0 侦查65 聆听20 说服35 心理学10 汉语49 母语49 攀爬40 斗殴60 闪避41 急救40
#    → 已更新 xx 项属性。
#      自动更新: 最大体力: 15, 理智上限: 99, 异变阈值: 15
```

```text
# 3. 检查：末尾会自动追加「异变阈值 / 本章累计损失 / 当前状态」三行
.st show

# 4. 检定
.ra 侦查              # 读卡里的侦查值（65）
.ra 侦查 60           # 指定值 60
.ra 困难侦查          # 困难（值 ÷ 2）
.ra 极难侦查          # 极难（值 ÷ 5）

# 5. 理智
.sc 1/1d6             # 成功损失 1 / 失败损失 1d6

# 6. 名片（可选）
.sn
```

录卡的四个要点：

1. **一次能写多少项都行**（v1.0.0 修复：旧版受 AstrBot 参数解析限制，只会写进前 2 项）。
2. **不要写 `取悦` / `话术` / `恐吓`**：本分支按修订版把社交技能合并为唯一的「说服」，写这三个词会被整条拒绝并提示改用 `.ra 说服`。
3. **`宗教` 必须带专长**：写成 `宗教（基督教）40`；裸写 `宗教` 会被拒绝。
4. **派生值自动算，不用手填**：最大体力 =（体质+体型）÷10、理智上限 = 99−克苏鲁神话、安抚 = 外貌÷5、异变阈值 = 意志÷5。手写 `安抚12` 会打上「手动」标记，之后改外貌不再自动重算。

## 三、指令速查

> 前缀统一 `.`（也认 `。` `/` `!` `！`）。绝大多数指令需要**在群里**使用。
> `@某人` 指 QQ 的 @，用于「代他人操作」或「以他人为目标」。

### A. 基础掷骰

| 口令 | 说明 |
|---|---|
| `.r` | 按当前规则默认骰：CoC = `1d100`，DnD = `1d20` |
| `.r 3d6` / `.r 1d6+5` | 指定骰式／算术 |
| `.r 3#1d10` | 连掷 3 次 |
| `.r4d6k3` / `.r4d6k-2` | 保留最高 3 / 最低 2 |
| `.r2d6rh` / `.r(2d6+1d8)rh` | 整组重投取高 |
| `.r2d6!3` | 满点追加骰（`!3` = 3 及以上追加） |
| `.r3d20min10max15` | 单个骰子限幅 |
| `.r1d20+5>=15` | 结果达标判定 |
| `.rd20` / `.rd 20` | Dice! 习惯写法，等同 `1d20` |
| `.rh 1d100` | 暗骰，结果私聊发你 |
| `.d66 [次数]` | D66 |
| `.jrrp` | 今日人品 |
| `.choose A B C` / `.choice A\|B\|C` | 随机选一（空格、`/`、`\|`、`,`、`，` 都能分隔） |
| `.rv [骰子数] [难度]` | 吸血鬼规则检定 |
| `.fire [normal\|accuracy\|recoil] [技能值] [+bN/+pN]` | 手枪三连检定 |
| `.fireball [环数]` | 火球伤害骰（默认 3 环） |
| `.adv` / `.dis` / `.adv+3` / `.dis-2` | DnD 优势 / 劣势 |

### B. 技能 / 属性检定

| 口令 | 说明 |
|---|---|
| `.ra 侦查` | 读当前卡数值检定；卡里没有则用 CoC 默认值 |
| `.ra 侦查 60` | 指定数值 |
| `.ra 困难侦查` / `.ra h侦查` | 困难（÷2） |
| `.ra 极难侦查` / `.ra e侦查` | 极难（÷5） |
| `.ra 侦查+10` | 带修正值 |
| `.ra3#b2射击50` / `.ra3#p2射击50` | 3 次，每次 2 奖励骰 / 2 惩罚骰 |
| `.rab [数量] 侦查` / `.rap [数量] 侦查` | 奖励骰 / 惩罚骰 |
| `.rah 侦查` / `.rch 侦查` | 暗骰检定（结果私聊） |
| `.rau 侦查` | 连续检定直到成功，输出总次数 |
| `.rav 侦查 a50/b60` | 对抗检定（指定双方数值） |
| `.rav 侦查 @对手` | 对抗检定（读双方卡） |
| `.rc 侦查` | Dice! 习惯写法，等同 `.ra` |
| `.en 侦查` | 技能成长检定 |
| `.alias add 侦察 侦查` / `.alias list` / `.alias del 侦察` | 技能别名 |

### C. 理智 · 惊骇 · 异变 · 安抚

| 口令 | 说明 |
|---|---|
| `.sc 1/1d6` | `<成功损失>/<失败损失>`，判定失败才吃大损失 |
| `.sc 2/1d10+2` / `.sc 1d4/1d20` | 支持骰式损失 |
| `.sc 1/1d6 @某人` | 为指定目标做理智检定 |
| `.ra 安抚 @某人` | 安抚检定（外貌÷5）：成功 +2 SAN（不超理智上限）、每章一次、结束惊骇；大失败 −1D4。**不 @ 或 @ 自己直接拒绝** |
| `.shock` | 场外惊骇：给三个互不相同的 1–10 编号，表由 kp 自备（插件不内置，防泄底） |
| `.sc reset` / `.sc 清零` / `.sc 归零` | **仅管理员**：清本章状态（累计损失／异变／惊骇／余悸／安抚标记／迷失），SAN 与技能不变 |
| `.ti` / `.li` | 旧症状表已停用，只回一句弃用提示 |

**自动触发，不用输入：**

- 单次理智损失 ≥ **5**（已异变则 ≥ **10**）→ 自动掷 INT；成功进入**惊骇**，输出五种反应之一 + `1D10` 轮持续时间 + 余悸。
- 惊骇期间再 `.sc`：骰子照常显示，但**损失按 0 结算**并提示。
- SAN 归 0 → 输出**迷失**。
- 本章累计损失达到 `意志÷5`（异变阈值）→ 提示**异变**，只提示一次。
- `.st show` 末尾固定三行：异变阈值 / 本章累计损失 / 当前状态。

### D. 人物卡管理

| 口令 | 说明 |
|---|---|
| `.pc new 文武` / `.pc create 文武` | 新建并绑定到当前群 |
| `.pc list` | 列出本群可见卡与序号，带 `(当前)` `(隔离)` `(全局)` 标记 |
| `.pc show [名字\|序号]` | 查看指定卡（不切换绑定） |
| `.pc tag [名字\|序号]` / `.pc change …` | 绑定/切换当前卡；**不带参数 = 解绑** |
| `.pc update <表达式>` | 等同 `.st`（Dice! 习惯） |
| `.pc rename 新名` / `.pc rename 旧名 新名` | 改名 |
| `.pc del <名字\|序号>` / `.pc delete …` | 删除卡并清理绑定 |
| `.pc push` | 把当前卡刷新到全域档案（全局卡则同步） |
| `.pc push global` | 把当前卡设为**全局卡**，之后所有群共用一份 |
| `.pc push local` | 给当前群做一份**本地副本**，之后本群改动不影响全局 |
| `.pc fetch` | 列出你名下**所有群 + 档案库**里的卡（按更新时间倒序编号） |
| `.pc pull <序号>` | 把 `fetch` 列表里的第 N 张卡拉到本群并绑定 |
| `.pc pull <序号> global` | 拉回来的同时设为全局卡 |

**`.pc fetch` / `.pc pull` 细节（上游文档没写，这里补全）：**

```text
.pc fetch
跨群人物卡列表：
1. 文武 (最新来源:全局 | 11-17 14:52)
2. 老张 (最新来源:1093458853 | 11-10 09:31)
使用 .pc pull <序号> 拉取人物卡。
```

- 全域扫描所有群目录 + 中央档案库，**同一个 uuid 只保留修改时间最新的那一份**，按时间倒序编号。
- `最新来源:全局` = 来自档案库（跨群共享的那份）；`最新来源:<群号>` = 来自某个群的本地副本。
- 编号只在**此刻**有效，之后建卡/改卡请重新 `fetch`。
- `.pc pull` **只认序号，不认卡名**；`.pc pull` 内部会重算列表，所以不强制先 `fetch`，但序号要按 `fetch` 的结果理解。

`pull` 的三种走向：

| 情况 | 行为 | 回应 |
|---|---|---|
| 目标已是全局卡，或加了 `global` | 绑定为全局卡，**不复制文件** | 已将 <名> 作为全局人物卡绑定至当前群组 |
| 本群已有该卡且不比远端旧，但当前绑的是别的卡 | 只切换绑定 | 已拉取人物卡：<名> |
| 本群没有，或本群副本比远端旧 | **物理复制**一份到本群并绑定 | 已拉取（新）/ 已同步（覆盖更新） |
| 序号越界 / 列表为空 | 不动任何数据 | 未找到可拉取的人物卡 |

**删卡的三个注意点：**

1. 序号按**卡名排序**生成，删掉一张后面的会前移 → 多张连删建议**用名字删**，或从大序号往小删。
2. 普通卡/全局卡删除是**真删**：档案 + 所有群副本 + 所有群的绑定一起清掉（其它群也会消失）；只有 `.pc push local` 出来的隔离副本才是「只删本群」。
3. 删掉当前绑定的卡后，`.st` 会回「当前群组尚未绑定人物卡」，需要重新 `.pc create` / `.pc tag`。

## 四、本分支的规则改造

对照 CoC 第七版修订版，本分支相对上游 `v2.3.2` 的差异：

| # | 改动 | 说明 |
|---|---|---|
| 1 | **社交技能合并** | 删除 `取悦`／`话术`／`恐吓`，只保留 `说服`（默认 10）。**不迁移旧卡旧值**：旧卡里写着「话术 60」，`.ra 说服` 仍按 10 算。`.ra`／`.st` 遇到这三个名字会提示、不执行 |
| 2 | **安抚** | 派生技能 = 外貌÷5。成功 +2 SAN（封顶理智上限）、每章一次、结束惊骇；大失败 −1D4。只能用 `.ra 安抚 @他人` |
| 3 | **宗教专长制** | `宗教` 进专长默认表（10），裸写「宗教」被拒绝，需 `宗教（基督教）` 形式 |
| 4 | **惊骇** | 单次损失 ≥5（已异变 ≥10）→ 掷 INT，成功进入惊骇：五种反应 + `1D10` 轮 + 余悸；惊骇中不再损失理智；SAN 归 0 = 迷失 |
| 5 | **场外惊骇 `.shock`** | 只输出三个互不相同的 1–10 编号，**表格不进插件**（避免泄底），带参数会提示不带参数 |
| 6 | **异变** | 阈值 = 意志÷5，按章累计 `san_loss_chapter`，达阈值提示一次；`.st show` 末尾追加状态三行 |
| 7 | **`.sc reset`** | 管理员手动清零本章状态（兼容 `清零`／`归零`），不动 SAN 与技能 |
| 8 | **`.ti` / `.li` 弃用** | 旧「临时性／长期疯狂」表停用，只回一句弃用提示 |
| 9 | **文案规范** | 玩家可见文案统一称 **kp**，不出现「守秘人／主持人／DM」，不写页码 |
| 10 | **长参数截断修复** | `.st`／`.pc update`／`.st show`／`.st del`／`.st export`／`.pc show`／`.choose` 改回读原始消息，不再只处理前 1~2 个词 |

术语对照（修订版）：惊骇 Shock / 余悸 Aftershock / 异变 Changed / 迷失 Lost，取代旧版的「疯狂发作／临时性疯狂／不定性疯狂／永久性疯狂」。

## 五、数据存放与备份

人物卡与日志写在插件目录同级的 `chara_data/`：

```text
chara_data/
├── user_metadata/<QQ号>/
│   ├── bindings.json                # 绑定表：哪个群 → 哪张卡
│   └── vault/coc/<uuid>.json        # 全局卡本体（跨群共用一份）
└── <群号>/<QQ号>/coc/<uuid>.json    # 群内副本（.pc push local 后才有）
```

- **两条指令靠什么串起来**：`.pc create` 写入 `bindings.json` 的「本群 → uuid」，`.st` 读同一个 uuid 写回卡本体。卡名只在 `.pc tag` / `.pc show` / `.pc del` 时用于查找序号。
- **绑定按群隔离**：A 群建的卡在 B 群要 `.pc fetch` + `.pc pull` 才能用。
- **备份**：直接备份整个 `chara_data/` 与 `component/config.yaml`（若有自定义文案）。升级不会自动删除旧数据。

## 六、常见问题

**Q：群里发指令一点反应都没有，日志也没有报错。**
按 [一、必做的四项配置](#一必做的四项配置) 检查唤醒词（`.`）与白名单（群号）。判断依据：`.r` 有反应、`.st` 没反应 → 就是唤醒词问题。

**Q：`.st` 只写进去了两项属性？**
已在本版本修复。旧版受 AstrBot 位置参数解析限制（`attributes, exp` 两个形参只吃前两个词），第四个词之后全部丢弃，导致「最大体力 0 / 异变阈值 0 / 说服按 10」。升级后重新发一次长串即可，不用重建卡。

**Q：日志里报 `retcode=1200 设置群名片未生效`。**
机器人不是群管理员。把机器人设为群管理员即可；属性已正常保存，这条只影响名片。

**Q：`.st` 报「只有『说服』这一项社交技能」。**
按修订版，`取悦/话术/恐吓` 已删除。去掉这三项再录，检定改用 `.ra 说服`。

**Q：`.ra 安抚` 提示「只能用于他人」。**
安抚必须 `@` 别人，且不能 `@` 自己。

**Q：`.sc reset` 没反应/被拒。**
只有插件配置 `admin_ids` 里填的 QQ 能用（或 AstrBot 全局管理员列表）。管理员判定**只看配置**，不看群主/群管理员身份。

**Q：旧卡里的「话术 60」能不能保留？**
不能，也不该。修订版把社交统一到「说服」，旧值不迁移；想保留请在卡里手动写 `说服 60`。

## 七、安装

1. 克隆本分支：

   ```bash
   git clone -b coc7r https://github.com/CZ-Izaya/astrbot_TRPGdice-Complete.git
   ```

2. 把插件目录放进 AstrBot 的 `data/plugins/` 下。
3. 安装依赖：

   ```bash
   pip install -r requirements.txt
   ```

4. 如需自定义回复文案（可选）：

   ```bash
   cp component/config.default.yaml component/config.yaml
   ```

5. 如需 `.find` 的图片卡片输出，安装 Playwright 的 Chromium：

   ```bash
   python -m playwright install --with-deps chromium
   ```

   AstrBot 官方 Docker 容器内：

   ```bash
   docker exec -it astrbot bash
   python -m playwright install --with-deps chromium
   ```

   容器内无权限装系统依赖时，用自定义镜像：

   ```dockerfile
   FROM soulter/astrbot:latest
   RUN pip install playwright \
       && python -m playwright install --with-deps chromium
   ```

6. 重启 AstrBot，确认控制台已加载本插件，然后按 [一、必做的四项配置](#一必做的四项配置) 配好唤醒词与白名单。

## 八、附加工具：日志染色器

`log-painter/` 内置一套类似 [海豹 LOG 染色器](https://log.weizaima.com/) 的前后端（模板与思路来自海豹，致谢）。

一键启动：

```bash
cd log-painter
./start.sh
```

脚本会创建 `.venv`、装依赖、构建前端并后台启动。完成后面板在 `http://localhost:5173`，后端在 `http://localhost:8000`。

常用管理：`./start.sh status|logs|stop|restart`；改端口：`BACKEND_PORT=8001 LOG_PAINTER_PORT=5174 ./start.sh`；运行文件在 `log-painter/.runtime/`。
